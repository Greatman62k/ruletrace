# UD-42: Diagnostics scope of the application reports

Confirmed by the user on 2026-11-18, deciding findings F1 and F2 of `docs/reviews/2026-11-18-review-corr3-366a80e.md`.

- **F1: requirement amendment required.** The design note alone is not enough for a new member of the closed report field set. New Req 31.16 defines the JSON member `diagnostics_scope`: a mandatory string, the only permitted value `evaluation_and_provenance`, placed immediately after `diagnostics` as the last top-level member, in the Prize_Check and Bracket_Check reports. Its meaning: the Diagnostics section lists evaluation and provenance-verification Diagnostics; published-result differences are reported only in the published-result section; Warnings on the standard error of `ruletrace evaluate` are outside the section. Req 31.6 and 32.5 reference it. The dated design §8.5 note stays as rationale. No other field, order or semantics changes.
- **F2: no published-result code in the Diagnostics section of a test document.** The hand-built report documents and the escape test of `crates/rt-explain` used `RT-EXE-0011` as their Diagnostic; they now use a genuine evaluation Diagnostic (`RT-EXE-0001`, a missing input of the Indeterminate score in the same document). No public API or model validation changes.
