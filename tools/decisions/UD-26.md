# UD-26: exit code with blocking semantic outcomes

Registered against: `propose` exit codes (tasks 8.7 and 8.8). Requirements 16.16, 30.2, 30.3, 23.35, 23.36, 27.8.

## Decision

The user confirmed the recommendation:

A structurally valid and provenance-verified batch that is successfully stored, but has blocking semantic findings, exits 0 with the Warning `RT-AI-0305`.

1. Such proposals remain Proposed and cannot be approved or compiled while blocking findings remain.
2. Malformed responses, invalid provenance and provider failures remain failures.
3. Partial multi-request runs remain explicitly incomplete (`RT-AI-0306`, exit code of the failing request).

## Comparison

| Option | Exit code | Reflects what happened | Risk | Verdict |
| --- | --- | --- | --- | --- |
| Exit 0 with Warning `RT-AI-0305` | 0 | The batch was accepted and stored; findings are data, not a failure | Scripts that ignore warnings may miss findings. The proposals are non-executable regardless. | **Chosen** |
| Dedicated nonzero exit code | new code | Mixes a successful store with failure | Breaks pipelines for a normal outcome; contradicts "semantic outcomes are not failures" | Rejected |

## Consequences

- No semantic outcome counts toward exit codes 3, 5 or 6 (Req 30.3).
- The Warning is emitted once per stored batch.
- Protocol failures (transport, schema, provenance) still reject the whole batch with their own codes.
