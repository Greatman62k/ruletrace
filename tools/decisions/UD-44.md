# UD-44: LT-7 bound, RN-50 and the lifeline option

Confirmed by the user on 2026-11-20, after the LT-7 prototype evidence
`docs/security/2026-11-20-lt7-lifeline-evidence.md` (reviews
`docs/reviews/2026-11-20-review-lt7ev-263a662.md`,
`docs/reviews/2026-11-20-review-lt7ev2-263a662.md`).

- **Bound.** The crash-test bound of design §11.18.6 is 5 s from the kill of the
  parent to the absence of every child. Basis: the prototype maximum was
  109 ms (five children back to back, Windows, one run per platform on
  GitHub-hosted runners), so 5 s is about 45.9 times that maximum with 4,891 ms
  of headroom. This is a test acceptance limit, not a guarantee for every
  system or load. It is measured again with the real executables.
- **RN-50.** Confirmed: `ruletrace` and `ruletrace-ai` get the option
  `--lifeline-stdin` of design §11.18.6 (mechanism L). With the option, the
  process runs one watcher thread that blocks reading standard input.
- **Exit with a Diagnostic (user decision, option A of the review
  `docs/reviews/2026-11-20-review-ud44-9467e45.md`).** When the watcher reads
  end of file, or a read error that is not recoverable, the process writes the
  Diagnostic `RT-CLI-0007` (mnemonic `CLI_LIFELINE_CLOSED`, Severity Error,
  exit 70, executables `rt, ai`) to standard error and exits with code 70. An
  error while writing that Diagnostic is ignored, because the parent may be
  gone. An interrupted read (`ErrorKind::Interrupted`) is retried and is not a
  stop. This keeps Req 5.12 (an exit 70 writes a Diagnostic of Severity Error
  that identifies the failure) and the rule that every failure mode has one
  code; no requirement text changes. The new code goes through the
  catalogue-change procedure. A read error going beyond end of file is a
  decision of the user, made here; the design named only end of file.
  Without the option nothing changes, and no existing output changes.
- **Scoped exception to the 13.1 gate.** Task 13.3 (as amended by UD-39) blocks
  the lifeline part on 13.1, and UD-39 section E item 4 keeps Laboratory
  implementation blocked until LT-6 and LT-7 are resolved and L1 is approved.
  The user instructs that `--lifeline-stdin` and its tests are implemented now.
  The exception covers only that option, its tests and their records. The rest
  of 13.3, and all `ruletrace-lab` code (13.4 onward), stay blocked as before.
- **Tests required.** On Linux, macOS and Windows, with the real `ruletrace` and
  `ruletrace-ai` executables: orderly closure of the pipe ends the child with
  exit code 70; killing the process that holds the write end leaves no child
  after the 5 s bound; a control without the option shows the child still
  running; each test is shown to detect its defect.
- **Still open after this decision.** LT-7 stays OPEN until the real-executable
  tests pass on the three platforms, V-1, V-2 and V-4 are addressed, and an
  independent reviewer accepts the mitigation in the threat model. LT-6 stays
  OPEN (browser protocol, check order, Req 37.5 and 37.6). 13.1 stays `[-]` and
  13.9 stays `[ ]`.
