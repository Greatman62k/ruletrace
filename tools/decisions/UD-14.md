## Exit codes per executable

| Executable | Codes |
| --- | --- |
| `ruletrace` | 0, 2, 3, 4, 70 |

A test asserts that no other value occurs (Req 27.10, 31.12). When several failures apply, the earliest stage of the executable's order decides. Warnings never decide.

## Classification (design §6.1)

- **2, invalid input**: unreadable, malformed or oversize file; unknown command or argument; Rule_IR syntax, literal or version problem (including an unrecognized IR_Version); ledger or store integrity failure; Source_Model missing or hash mismatch; missing review target; contradictory flags; AI configuration and request problems.
- **3, blocking result**: blocking Diagnostics of `validate` and `compile` (including `APPROVAL_UNRESOLVED`), and refused `review` actions.
- **4, Indeterminate Outcome at `evaluate`**: includes a runtime conflict (`RT-DGN-0004`) and empty min or max (`RT-DGN-0005`). Never 3 (Req 16.23, UD-13).
- **70, internal error or failed write**: output write failure, ledger and rulebook commit failure, lock failure, Transmission_Log and store write failure, invariant violation.

## Source_Model codes (RN-10 split)

| Code | Mnemonic | Meaning | Exit |
| --- | --- | --- | --- |
| `RT-VAL-0017` | `VAL_SOURCE_MODEL_MISSING` | No Source_Model for a referenced document | 2 |
| `RT-VAL-0018` | `VAL_DOCUMENT_HASH_MISMATCH` | Declared hash differs from the Source_Model hash | 2 |
| `RT-VAL-0019` | `VAL_SPAN_OUTSIDE_DOCUMENT` | Span lies outside the Source_Model document | 3 |

RN-10: a missing or mismatched Source_Model is reported as a Diagnostic of validation (pass 2, Sources) but is classed as invalid input, so it exits 2. All other validation failures (for example `RT-VAL-0016`, `RT-VAL-0019`, `RT-VAL-0020`) are blocking results and exit 3. The exit code is the catalogue exit code of the Diagnostic that decides the run.
