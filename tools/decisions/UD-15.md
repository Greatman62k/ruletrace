## 2. Toolchain pin (DD-3)

- `rust-toolchain.toml` pins the full version `1.99.1` (`major.minor.patch`, no channel alias such as `stable`).
- Floor: 1.89, the first stable release with `File::try_lock`. 1.99.1 is above it.
- Evidence: `rustc 1.99.1 (58cf8f9c3 2026-10-13)` is the installed stable toolchain on the development machine. `rustup check` reports a newer release, 1.100.0 (2026-11-09), which is not installed and was not used. Moving the pin is a deliberate, reviewed change to `rust-toolchain.toml`, never above-floor drift.
- Edition 2021 or later, as in design §3.1.

## 3. `File::try_lock`

Accepted. The `ruletrace review` commit protocol (design §3.8.3, protocol step 1) takes an exclusive advisory lock on `<ledger>.lock` with `std::fs::File::try_lock`. A lock failure is `RT-APR-0212` with exit 70. No lock crate is added.

Amended by the user's fail-closed decision of 2026-11-14: the `create_new` lock-file fallback is removed, and a file system without advisory locks is refused with `RT-APR-0215` (exit 70) by readers and review commands.

Fallback, not adopted: if `File::try_lock` were not accepted, the pin could stay below 1.89 and the lock would use a `create_new` lock file, with `RT-APR-0212` when it already exists. That variant leaves stale lock files after a crash.

## 6. `live-openai` secret and variable (user-approved 2026-11-16, task 10.5)

Status stays Confirmed. This section records the part of UD-15 that task 10.5 left open.

- Secret name: `RULETRACE_OPENAI_API_KEY`, a GitHub Actions repository secret. It is optional. The job `live-openai` in `.github/workflows/ci.yml` is not required and is not in the `needs` of `ci-gate` (design §7.4, Req 21.14).
- Model: the optional repository variable `RULETRACE_OPENAI_MODEL` names the model. No model identifier is written in the repository.
- The job runs its live steps only when both the secret and the variable are non-empty. Otherwise it prints a notice that names which one is missing, runs nothing else, and concludes successfully. Fork pull requests have no secrets and skip in the same way.
- The secret is referenced only in the job-level `env`. It is never echoed and never written to a file. The configuration written at run time names the credential by variable name only, and is created with mode 600 under `$RUNNER_TEMP`. Nothing from the live steps is uploaded as an artifact.
- The default live step runs `ruletrace-ai models` only: an authenticated catalogue request with no document text. A live propose over the synthetic stand-in document runs only on a manual `workflow_dispatch` with the input `propose` set to true.
- The agent that added the job did not create the secret or the variable and made no live call. Whether the job runs against the real provider is unverified until the user configures them.
