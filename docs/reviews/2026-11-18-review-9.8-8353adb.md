## 4. Non-blocking findings

Severity: M = medium, L = low.

1. **F1 (L), APP-API is not implemented.** Design §8.10 lists a fourth rule, APP-API, with `tools/app-api-allow.v1`. The text of task 9.8 does not name it. It asks for arithmetic and order, literals, io, and edges "outside the application allowed list, directly or transitively". All of those are built. `app_layers.rs:1-60` documents nine rules and no APP-API. The status note in `tasks.md` records the omission. Judgement: 9.8 does not require it. The design table does, so either the design needs a line saying the allow-list is replaced by the edge list plus `app-order` and `app-numeric`, or a later task must build it. Needs an explicit decision. The gap is real: `use rt_engine::<internal>` passes if the edge `app -> rt-engine` is listed, which it is (`tools/allowed-edges.v1:25`).
2. **F2 (L), negative fixtures are in-test strings.** Design §8.10 puts them under `tests/fixtures/app-scan/`. 9.8 says "negative fixture per violation class", and `app_layers_tests.rs` and `tests/app_layers.rs` satisfy that with hand-counted lines. Every Req 31.10 class has a test asserting rule, crate, file and exact line through `fails_once`:
   - arithmetic: `add_fails_on_its_line`, `subtract_`, `multiply_`, `divide_and_remainder_`, `assignment_forms_`
   - compare: `ordering_comparisons_`, `equality_of_exact_number_operands_`
   - sort, min/max, aggregate and round
   - tie-break, rounding mode, literal weight or threshold, field name
   - io
   - edges

   The design text is not followed literally. The status note discloses this.
3. **F3 (M), equality of plain variables is not flagged.** `a.score == b.score`, `score_a == score_b`, `a.eq(&b)` and `a.ne(&b)` all pass. By design `==` is flagged only when a numeric marker (`ExactNumber`, `to_canonical` and others) is within the operand window (`app_layers.rs:~500-560`). Req 31.10 says "compares ... Exact_Number values". An application that detects ties by comparing two score values bound to plain variables passes the scan. The design says the scan is an early alarm and that Properties 42 and 43 are the evidence. The gap is by design and disclosed in the module docs. Not blocking, because `<`, `>`, `<=`, `>=`, `cmp` and `partial_cmp` are all caught and equality alone does not give an order. Recommend recording it in the claims or limitations text.
4. **F4 (L), BTree selection passes.** `m.iter().next_back()`, `last_key_value()`, `pop_last()`, `.last()`, `.first()` and `.nth` pass (probed). They select a maximum or a ranked position from an ordered collection. Mitigation: `BTreeMap` and `BTreeSet` are keyed by identifiers by design (§8.10), and the byte-identity and metamorphic tests cover results.
5. **F5 (L), filesystem use through a `Path` value passes.** `p.exists()`, `p.is_file()` and `p.metadata()` pass because they name no `std::fs` module or `File` identifier. `app-io` flags `std::fs`, `std::env`, `std::process`, `std::io`, `std::net`, `std::time`, `std::thread`, `Instant`, `SystemTime`, `File`, `Command`, `rand` and several macros. Realistic only if a library takes a `Path`, and the `std::path` import is not flagged either. Req 31.11 byte-identity under two working directories (task 9.17) is the backstop, and it is not yet delivered.
6. **F6 (L), uppercase-leading identifiers are treated as generics.** `A < B` with uppercase variable names, or `Foo::X < b`, is read as a generic bracket (`type_like`, `app_layers.rs:~478`). Rust variables are lower-case, so this is unrealistic. A `<<` shift is reported as a comparison (false positive, harmless).
7. **F7 (L), a derived `PartialOrd`/`Ord` passes.** `#[derive(PartialOrd)]` is not flagged. Using it needs `<`, `cmp` and so on, which are flagged.
8. **F8 (L), the `Lab` class path is untested in the edge rules.** The mutant that drops `Class::Lab` from `check_app_edges` (`graph.rs`, `layers` closure) survived. The `Class::Lab` parse test exists (`edges.rs lab_is_a_class_word`), but no test builds an `rt-lab` edge set. `layers()` in `app_layers.rs` also takes `Class::Lab`, untested. Task 13.4 must add that test in the commit that creates `rt-lab`. Today no crate has the class, so there is no live defect.
9. **F9 (L), `layers()` silently skips a listed app crate whose `src` is missing.** The integration test pins `scanned.crates == 2`, so the real workspace is protected. A synthetic repo with a listed app crate and no directory passes with 0 crates. Low risk.
10. **F10 (L), `tools/app-literals.v1` uses `*` for seven entries.** For example `"participants"`, `"collections"` and `"published"` are valid for any checked crate. Each entry has a reason, is used in both crates (`prepare.rs:17-19`, `:125`; `questions.rs:57-97`), and no entry is a name from the 23 committed rulebooks (`validate_literals`). Acceptable. When rt-lab arrives, `*` extends to it silently.
11. **F11 (L), the integration test header says it validates Req 31.11 and 24.12.** 31.11 also needs the clock, working-directory and locale test (9.17), and that test is not built. The status note states that. The doc header over-claims slightly. 27.15 is not claimed anywhere: `executables.rs:1-12`, the `tasks.md` status note and `tools/executables.v1` all say it waits for 13.4.

## 5. What held up

- **Positive run is not empty.** `rt-xtask check-app-layers` prints `ok (2 crates, 25 files, 23 rulebooks, 2 edge sets)`. `tests/app_layers.rs::the_workspace_passes_the_source_rules` asserts `crates == 2`, `files >= 12` and `rulebooks >= 1`. Production-token counts per file (probe, `production_tokens`): prize-check evaluate 527, prepare 977, questions 754, report 921, lib 84, mapping 58, classify 15. The `tests_*.rs` files are skipped through the `#[cfg(test)] mod` declarations. Injecting `fn injected(a,b){ a + b }` at the end of the real `prize-check/src/report.rs` made the command fail with `[app-arith] prize-check: src/report.rs:148: operator +` and exit 1. The source was restored.
- **Real edge and binary mutations fail as specified.** Adding `rt-cli` to `bracket-check/Cargo.toml` failed with `edge-not-allowed` and `forbid-transitive` (`rt-cli`, `rt-compile`, `rt-ledger`). A `src/bin/x.rs` in `prize-check` failed `check-executables` with `[app-binary] ... binary target 'x'`. Both were restored.
- **Req 31.10 detection rules.** Each class has a rule and a test (F2 list). Probes that were flagged:
  - `a < b`, `a > b`, `a <= b` and `a.value() > b.value()`
  - `a.score < b.score`, `a[0] < b[0]` and `Wrapper(a) < Wrapper(b)`
  - `max_by_key`, `iter().max()`, `sum`, `cmp`, `is_lt`, `std::cmp::max` and `.add()`
  - `"0.6".parse()` (the literal "0.6" is unlisted), a float literal, `0x10`, `2` and `[0, 2]`
  - `"goals"` as a normal, raw or byte string
  - `"go" + "als"` pieces (each piece is an unlisted literal)
  - `rt_numeric` aliasing and glob
  - `std::fs`, `std::env`, `std::process`, `std::io`
  - a `#[cfg(not(test))]` function, a `macro_rules!` body and a `matches!` guard
  - a `#[test]` function followed by a production function with arithmetic is still scanned

  Probes that pass are classified in section 4: F3 to F7. A listed layer-text literal such as `"--score".parse()` passes, which is correct.
- **`tools/app-literals.v1`.** The string-literal check is default-deny. A name that a rulebook declares fails at `app-field-name` even if listed (mutant killed). `validate_literals` refuses to run with a listed rulebook name (mutant killed). Tie-break, rounding-mode and number checks come before the listed test. The check refuses to run with zero rulebooks (`[app-names]`; mutant killed by `without_a_committed_rulebook_the_check_refuses_to_run`).
- **check-executables.** `tools/executables.v1` holds exactly `ruletrace` in `rt-cli` and `ruletrace-ai` in `rt-ai-tool`. A binary in an app package fails. Tool and test classes are excluded by rule (test `conforming_workspace_passes_and_tool_and_test_bins_are_excluded`). An unclassified package with a bin fails. Missing, extra and wrong-package entries fail. A package without a `targets` array is reported as malformed metadata, not as "no binary". 27.15 is not claimed.
- **Graph and class additions are additive.** `git diff 663f87a..8353adb -- crates/rt-xtask` removes only: the `Metadata` import line (replaced by `{DepKind, Metadata}`), the old USAGE line, the old `check-decisions` match arm, and the old `Ok(Metadata { members, resolved })`. No test line is removed or changed. `check_graph` is unchanged. The `app-external` rule exempts only dev-dependencies, and `check_external` (forbid-external and external-not-allowed) still applies to them. `tools/allowed-edges.v1` is untouched.
- **CI.** The diff is one line: the command line of the `graph` job gains `check-app-layers check-executables`. Nothing else changed in `.github/`. CI itself was not run.
- **Test integrity.** Expected lines in the negative tests are hand-counted literals in the source strings, not computed from the scanner. No ignored or skipped tests. No golden file touched.
