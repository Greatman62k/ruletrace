## 3. Blocking findings

### B1. An external caller can show `verified` and invented source text without the Explainer (Req 31.14)
Evidence (reading): `Evidence { trace, verified: bool, rules, sources }` (`model.rs`), `ProvenanceSummary::Verified { traces }`, `ReportHeader`, `EligibilityEntry`, `ScoreEntry`, `StandingsTable`, `QualificationEntry` all have public fields. `SpanVerdict` (`verify.rs:35`) has public fields, and `SpanResolution::Resolved(String)` is a public variant. Only `Verification` is sealed (private fields, produced only by `verify_trace`). `ReportDoc::new` validates section set, order, duplicates and kind/code pairs, but not that the header and entries agree and not that `verified` came from a `Verification`. `from_trace` and `from_verifications` are the intended path and are correct, but they are not the only path.

Proof: scratch integration test `crates/rt-explain/tests/scratch_forge.rs` in the worktree (deleted with it). It uses only `rt_explain`, `rt_foundation`, `rt_trace`.
```rust
use rt_explain::report::{render_human, render_json, EligibilityEntry, Evidence, ProvenanceSummary,
    ReportApplication, ReportDoc, ReportHeader, ReportSection, Sha256Hex, StatementId, Truth};
use rt_explain::{SpanResolution, SpanVerdict};
use rt_foundation::{DocumentId, RevisionNumber, RuleId};
use rt_trace::TraceSpan;

#[test]
fn external_caller_can_forge_verified_without_explainer() {
    let h = Sha256Hex::new(&"a".repeat(64)).unwrap();
    let forged = SpanVerdict {
        rule: RuleId::new("r1").unwrap(),
        revision: Some(RevisionNumber::new(1).unwrap()),
        span: TraceSpan { document: DocumentId::new("rules.md").unwrap(), sha256: h.clone(),
                          start: 0, end: 5, line: 1, column: 1 },
        resolution: SpanResolution::Resolved("INVENTED SOURCE TEXT".to_owned()),
    };
    let evidence = Evidence { trace: 0, verified: true,
        rules: vec![(RuleId::new("r1").unwrap(), RevisionNumber::new(1).unwrap())],
        sources: vec![forged] };
    let entry = EligibilityEntry { participant: "p1".into(), target: "eligible".into(),
        result: Truth::True, evidence };
    let header = ReportHeader { application: ReportApplication::PrizeCheck,
        statements: vec![StatementId::new("ST-BOUNDARY")], rulebook_hash: h.clone(),
        input_hashes: vec![("data", h)],
        provenance: ProvenanceSummary::Verified { traces: 1 }, synthetic_data: Some(true) };
    let doc = ReportDoc::new(header, vec![ReportSection::Eligibility(vec![entry])]).unwrap();
    // asserts: "provenance: verified (1 of 1 traces)", "trace #0  verified",
    // "INVENTED SOURCE TEXT", and "\"verified\":true" in the JSON
}
```
A second test, `header_and_entries_can_disagree`, builds header `NotVerifiedNoSources` with an entry `verified: true`; `ReportDoc::new` accepts it, and the output carries both statements.

Result: `cargo test -p rt-explain --test scratch_forge`: 2 passed, 0 failed (exit 0). Output of the first test:
```
provenance: verified (1 of 1 traces)
ELIGIBILITY
  p1  eligible  true
      trace #0  verified  rules r1@1
      source r1@1 rules.md 0..5 line 1:1
        "INVENTED SOURCE TEXT"
... "provenance":{"status":"verified",...},... "verified":true ... "text":"INVENTED SOURCE TEXT"
```
Other paths: no `Default` impl, no parser, no `Deserialize`, no JSON input that sets `verified` (`grep from_str|fn parse|Deserialize|impl Default|impl From` in `report/*.rs` outside tests: no match). `Clone` copies only what exists. So the only holes are public fields and variants.

Why blocking: Req 31.14 and the steering say `verified` is shown only when the Explainer said so. The type system does not enforce it, and the report can also print source text that was never resolved. The partial review rated this non-blocking. I rate it blocking because it is the primary trust boundary of this task and the fix is local: private fields on `Evidence` and the entries, constructors taking `&TraceRef` or `&Verification`, a `ProvenanceSummary` that only `from_verifications` builds, and a cross-check in `ReportDoc::new` that summary and entries agree.
