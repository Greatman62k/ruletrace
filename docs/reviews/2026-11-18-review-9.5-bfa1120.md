## 4. Non-blocking findings

1. **Medium. `ResultClass::of` duplicates the private classification of `rt-cli`.** `crates/prize-check/src/classify.rs:38-57` repeats `rt-cli/src/evaluate.rs:533-575`. I compared the two by eye: the order (question fault, then indeterminate or engine Error, then provenance Error) and the predicates are identical today.
   - Risk: the two copies can drift. The only guard is the differential test `rt-tests-core/tests/prize_check_exit_codes.rs`, which covers six data cases plus one invalid-question case. It does not cover class `Internal` (70) against the CLI, and it has no case where an engine Error Diagnostic arrives with all Outcomes decided. That case is pinned only by the synthetic unit test `tests_classify::an_evaluation_error_is_indeterminate_even_when_every_outcome_is_decided`.
   - Conflict: design 11.18.7 says the Laboratory takes the class from the exit code of the `ruletrace` subprocess and never maps exit 4 to "Indeterminate only". Req 31.12 as amended says the module returns a classification that `ruletrace-lab` maps. A public `ResultClass::of` in the Present group invites the Laboratory to classify on its own. `classify.rs` doc says `ruletrace-lab` "maps the four classes to the exit codes", which is the opposite of the design.
   - Recommendation: user decision. Either (a) move the predicate into one core crate that both `rt-cli` and `prize-check` may depend on (needs an allowed-edges and API-contract change), or (b) keep the copy, add the missing differential cases, and reword the `classify.rs` doc to say the Laboratory must use the subprocess exit code.
   - Testing policy section 2.7: the tests do not compute their expectation with production logic. `exit_code()` in `prize_check_exit_codes.rs` is a separate literal 0/4/2/70 table, and the expected codes in `cases()` are literals. No finding there.
2. **Low. Req 31.11 and 31.15 tests are not in 9.5 and not named in its pending list.** There is no test under two values of clock, working directory and locale (31.11), and no isolation test over two rulebooks (31.15). Tasks lines 1105 and 1171 schedule both elsewhere (9.8 and a later task), so this is a disclosure gap, not a missing deliverable. The status note lists 31.10, 31.4, 31.5, goldens and 13.3 only. The sentence "9.5 has no deferred part" sits next to a pending list that names parts of 31.x tied to this task's requirement tags (31.4). Reword it.
3. **Low. Req 7.23 as amended is not met by the catalogue.** All six `RT-APP-0001..0006` rows in `catalogue/diagnostics.v1.json` still say executable `pc, bc`; 7.23 says `ruletrace-lab`. The implementer disclosed this. `check-catalogue` passes, so nothing enforces it. Needs the `ruletrace-catalogue-change` process and a user decision.
4. **Low. A request with no Target gives an empty report and no Diagnostic** (`tests_report::a_request_without_targets_is_not_an_error_and_evaluates_nothing`). The test pins this as intended behaviour. No catalogue code covers it, so the library cannot do better. Task 13.3 or the Laboratory form must refuse an empty request, or the user must add a code. The test fixes a behaviour that is a placeholder.
5. **Low. No Comparison reaches Present from a results file.** `PresentInputs.comparison` is a typed `Option<&Comparison>`. The results file has none (disclosed), so task 13.3 must supply one or derive the differences from RT-EXE-0011..0013 Warnings. Until then the Laboratory path cannot use the Published section. Open point for 13.3.
6. **Low. No test of a Tie_Group in a Prize report.** `slice-basic` breaks the p2/p4 tie by `judges`, so Req 31.6's Tie_Group display is covered only by `rt-explain` tests. Golden coverage is task 9.16.
7. **Low. The source scan is name-based.** `prize_check_no_io.rs` flags identifiers such as `fs`, `env`, `time`. A crate alias or a re-export through a dependency would pass. The note admits it is the minimum before `check-app-layers` (9.8). The dependency test checks edges-line membership by substring (`line.contains(name)`), which is weaker than set equality. Neither is a defect today: `check-graph` passes.
8. **Note for 9.8.** `report.rs` compares `outcome != trace.outcome()`. That compares Outcomes for consistency, not Exact_Number values, but the 31.10 scan must not flag it as a ranking or comparison of its own.
