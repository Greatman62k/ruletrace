## 4. Non-blocking findings

Item 1 to 4 and 6 checks have no further findings except as listed.

**N1. ctrlc "uses `unsafe` internally" (UD-45 lines 34 to 35) is not
established.** The docs.rs page (https://docs.rs/crate/ctrlc/latest, fetched
2026-11-20) confirms: version 3.5.3, MIT or Apache-2.0, `termination` feature
for SIGINT, SIGTERM and SIGHUP, alternative `signal-hook`. It does not state
anything about `unsafe`. Remove the sentence or mark it "to be checked in 13.4".

**N2. SIGHUP.** The `termination` feature also handles SIGHUP. Req 37.17 and
§11.11 name only interrupt and terminate. UD-45 line 33 states the fact but not
that the behaviour on SIGHUP (orderly exit 0) is then a new, untested
behaviour. Say so, or require a test.

**N3. V-1/V-4 harness has no number and no coverage rule.** The statistical
limit is explicit (UD-45 lines 50 to 52), but N and the distribution of kill
points are not set. With no test hook in production code, kill times are
timing-based and can miss the narrow write steps. State a minimum N and that
the in-process fault tests, not the harness, are the per-step evidence (the
second half is already there). Also state that a harness failure to reach the
write window is "inconclusive", not a pass.

**N4. Draft 37.6 and 37.7 conflict after session end.** 37.6 says that after
the session ends every request is refused until restart. 37.7 refuses only
requests without valid credentials "for the current Launch_Secret". After the
end the secret is still current, so 37.7 does not cover it. Add the status
(401 or another) and challenge behaviour for valid credentials after the end.
Also, "ends as Requirement 37 criterion 17 and the idle limit state" (UD-45
lines 73 to 74) should cite 37.8 by number.

**N5. Draft 37.7 versus the check order.** 37.7 says a request without valid
credentials gets 401. UD-45 section 1 puts Host and Origin first, so such a
request can get 403. Word it "IF the Host and (for a state-changing request)
Origin checks pass AND ...". Putting a reference to a decision file into
requirement text (line 83) is fragile; write the order in the criterion.

**N6. The user name is not required to be shown.** Draft 37.5 fixes the user
name `lab` but does not require the terminal output to print it with the
secret. The user cannot fill the credential prompt otherwise. Req 37.23
(run instructions) should mention it.

**N7. Draft 37.5 drops "SHALL accept it once".** That is intended, but the
Launch_Secret definition (requirements.md:188) and RN-47/LT-5 reasoning rely on
"once". Covered by the consequences paragraph only for T12d and R-L7.

**N8. Prototype versus requirement.** The prototype ignores any `Cookie`
header (lab.rs:93 comment). Req 37.24 (cookie criteria) has no counterpart in
the draft; see the list below.
