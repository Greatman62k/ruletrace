## 5. What held up

1. **Behaviour unchanged (check 1).** Line-by-line comparison of old `classify` (8476acc, `evaluate.rs:533-575`) and new:
   - Old: `invalid_question = evaluation.diagnostics.as_slice().iter().any(is_question_fault)`. New: `has_question_fault(diagnostics)` with the same argument, `evaluation.diagnostics`, and the same predicate `code() == Code::QuestionInvalid`.
   - Old: `indeterminate = diagnostics.has_errors() || any Outcome::Indeterminate`. New: identical expression.
   - Old: `provenance = verifications.iter().any(|v| v.diagnostics().has_errors())`. New: identical.
   - Same priority order (fault, indeterminate, provenance, success) and same three-way mapping to `ExitCode`.
   - The merged `state` (diagnostics, verification diagnostics, published warnings) is built as before. The early exit at `evaluate.rs:445` is untouched: `code == InvalidInput && state has question fault` returns empty stdout, so nothing is written. Mutant M7 (disable it) is killed by `pipeline_tests::a_question_the_inputs_cannot_answer_is_invalid_input`.
   - `git diff --name-status` shows no golden or fixture file changed. The only test file modified is `prize_check_exit_codes.rs`, with 62 added lines and 0 removed lines. No `#[ignore]`, no removed assertion. `tests_classify.rs` is new.
2. **The table (check 2).** Sixteen rows cover every combination of (fault, indeterminate Outcome, engine Error, provenance Error). I re-derived all 16 from Req 16.14/16.17 (earliest stage), 16.23 (4 outranks 2 from provenance) and the fault-first order: fault gives 2 (rows 9-16), no fault with an Indeterminate Outcome or an engine Error gives 4 (rows 3-8), provenance only gives 2 (row 2), none gives 0 (row 1). All 16 match. `expected()` reads the constant table, not production code. The proptest uses `with_cases(256)`. Its generator varies four flags, a Warning flag, 0-4 decided Outcomes and an insertion position 0-7, and builds real `Outcome` and `Verification` values (a verification Error from a span whose document has no model, a verification Warning from an empty model set). A fixture test pins the severities the table assumes. Cases are not reduced.
3. **RN-38 finding (check 3).** In `rt-engine/src/lib.rs` the `Answer` for a decided Outcome carries `Vec::new()` diagnostics (`conclude`, `Eval::Known`). Every Error is built together with `Outcome::indeterminate`: `invalid` (RT-EXE-0010, lines ~249-275), `refused` (~283-310), `conclude` Unknown and Fault branches, and the dependency cycle branch (`None`, ~426). In `rank.rs`, `missing` is filled only in `order()` together with `Block::Indeterminate` (184-223), and `ranker.diagnostics` is derived only from `missing` (271, 490-494). The finding is stated as "fact, no decision taken" with its limit (Rule_IR version 1, a future construct could differ). The decision column and RN status are unchanged. The pinning test runs the real `ruletrace evaluate` over three data sets and asserts two Error cases. It is a sample, and the design text says "over the slice-basic cases".
