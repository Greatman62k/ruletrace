## 3. Blocking findings
B1. The fix treats any identifier before `::` as a path segment, and keywords are identifiers. A leading `::` after a keyword is therefore read as a continuation and not reported.

Evidence: a scratch test (since removed) ran `fn f() {\n<prefix>::rt_engine::evaluate(1);\n}` against an empty allow-list. It also ran `::rt_numeric::add`.
- Detected (1 finding each): none, `let _ =`, `f(`, `x = `, `g(a, `, `{ `, `; `, `&`, `!`, `Vec<`, `-> `, `x: `, `=> `, `+ `, `| `.
- Missed (0 findings): `as`, `return`, `if`, `dyn`, `impl`, `in`, `mut`, `match`, `else`, `move`.

Examples that pass `check-app-layers` undetected: `return ::rt_engine::evaluate(1)`, `if ::rt_engine::decide() {}`, `x as ::rt_numeric::T`, `impl ::rt_engine::Tr for X`.

Suggested fix: exclude reserved keywords from the "identifier" arm of `continues_segment`. Add one test per keyword class: expression (`return`, `if`, `match`), type (`as`, `dyn`, `impl`).
