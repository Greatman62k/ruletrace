## 4. Non-blocking findings
- N1 (needs user decision) `published.rs` map_published: a row for a declared Target of kind `Other` that was NOT requested gives RT-APP-0006. Design 8.3 says an unrequested published row "is not an error" and is listed in `published_unused`. Catalogue text of RT-APP-0006 says "Requested Target". The commit's reading conflicts with that sentence. Probe: requested={elig}, row `p1,oth,1` gives RT-APP-0006.
- N2 (needs user decision) A line ending in an unquoted comma is an error, so an empty last cell must be written `""`. Design lists "trailing separators" as errors, so it is not a contradiction, but spreadsheet exports write an empty last cell as `1,`. Such a file is rejected with RT-APP-0001 (clear message, no silent default). The alternative reading (a trailing comma is only an error when the cell count exceeds the header) is also consistent with the design.
- N3 Bad-number messages print the Debug name of the numeric error (`BadCharacter`, `TooManyDigits`). Cosmetic.
- N4 Reserved-name grouping differs from the JSON decoder: tabular gives RT-DGN-0002 for has_errors+no_errors only and a separate RT-DGN-0001 for another flag column (e.g. `passed`); `rt-json::check_flag_keys` names all flag keys in one diagnostic. Tabular follows the design text "one Diagnostic per occurrence" and Req 22.10 for the pair. Reasonable reading.
- N5 A declared input named like a reserved key (e.g. `passed`) cannot be used. Same rule as the JSON path.
- N6 Collections header must contain the union of all declared element fields (RT-APP-0002 otherwise), even for a file that uses one collection. Design is silent; reasonable reading.
- N7 Numbers in participants are stored as the literal given (`007`, `1.50`, `-0` accepted); published numbers are canonicalized (`1.50` to `1.5`). Matches the existing JSON data model (numbers are text). Reasonable.
- N8 `ruletrace`-writer identity: `data_bytes`, `questions_bytes`, `published_bytes` are thin wrappers of `serialize_*`, so "byte-identical" holds by construction. Tests compare with hand-written bytes and the committed demo `questions.json`.

Deviation judgement: Table carries an input id (reasonable, design silent). ByteLimit (the design signature already names it; only defined here: no deviation). map_published fourth argument (required by the design's unknown-participant rule; reasonable). TargetKind::Other and RT-APP-0006 at a published cell: for requested targets reasonable, for unrequested see N1. Trailing separator: N2. `#` comment lines: design says comments are errors; reasonable. NUL: extra rejection, not contradicted. Reserved grouping: N4. Quoted-cell column at the opening quote: matches "first character of the cell". Numbers as given: N7. Empty published value RT-APP-0004: reasonable (no Missing form in Published_Result, never defaulted). Collections header union: N6. Non-UTF-8 single diagnostic at `valid_up_to`: reasonable.
