## 4. Non-blocking findings

- F1 (Medium) `RULETRACE_BLESS=1` is not covered by rule (f).
  `crates/rt-tests-core/tests/golden/slice.rs:12,182` rewrites the expected
  files under the golden fixtures when `RULETRACE_BLESS=1`
  (refused only when `CI` or `GITHUB_ACTIONS` is set).
  `grep -n RULETRACE_BLESS tools/hooks/guard_shell.py` finds nothing, so
  `RULETRACE_BLESS=1 cargo test -p rt-tests-core --test golden golden_slice`
  is not blocked by (f). The same class of gap that this change closes.
  I did not execute this command through the guard, since the matching is by
  the literal names only; the source shows the names are absent from the regex
  and `BLESS_ASSIGN`. Writes to `tests/fixtures` by other means remain subject
  to the other rules, which I did not re-test. Recommendation: add
  `RULETRACE_BLESS` to the prefilter, `BLESS_ASSIGN` and the message, with the
  same tests, and consider one shared tuple of names so the three copies
  cannot drift apart.
- F2 (Low) The bless names are repeated in three places (prefilter regex,
  `BLESS_ASSIGN`, docs). A single list would prevent the drift that caused
  this defect and F1.
- F3 (Low) `tools/hooks/README.md:141-154` still names only `RT_DEMO_BLESS`
  and is not updated. Documentation is now inconsistent with behaviour.
- F4 (Low, pre-existing, parity with RT_DEMO_BLESS, not caused by this change)
  `ssh h env {V}=/x true` and `$'{V}'=/x true` are allowed for both
  variables. The guard header already states it is best-effort. Not in the
  user's scope for this change.
- F5 (Info) The new test strings use `/x` and `/r/...` placeholder paths.
  The approval test uses the intended command shape with `/r` in place of
  the real paths. Equivalent for rule matching.
- F6 (Info) The `BLESS_TEXT` line is 85 columns, longer than the other
  lines in that file. `rustfmt` does not apply (Python).
- Other variables found by grep (crates, tools, .github, demo): the
  names `REV1_GOLDEN`, `REV4_GOLDEN`, `DRAFT_GOLDEN` are Rust constants, not
  environment variables. `RT_DEMO_BLESS` (rt-demo) and `RT_APP_GOLDEN_BLESS`
  are covered. `RULETRACE_CI_PLATFORM`, `PROPTEST_CASES`, `CARGO`, `CI`,
  `GITHUB_ACTIONS` do not write goldens. A grep for `UPDATE_`, `*_ACCEPT`,
  `*_REGEN`, `INSTA*` found no match. `env::var` reads in the AI crates were
  not examined.

   RT_APP_GOLDEN_BLESS, through `guard_shell.py` in the scratch copy and

   The forms included direct assignment, `env`, `env -i`, `env FOO=1`,
   `env -u`, `env -C`, `env --ignore-environment`, `env -S` (quoted and
   attached), quoted names, `export`, `export -n`, `declare`, `typeset`,
   `readonly`, `local`, empty value, `+=`, `sh -c`, `bash -c` nested, `bash -lc`,
   `zsh -c`, `dash -c`, `eval`, `xargs env`, `find -exec env`, `nice`,
   `time`, `sudo`, `timeout`, `nohup`, `command`, heredoc into `bash` and `sh`,
   `&&`, `;`, subshell, command substitution, backticks, newline-separated
   commands, and a line continuation.
2. Read-only mentions stay allowed (exit 0, both variables): `grep -rn V
   crates`, `rg V=/x`, `echo V=/x`, `cat <<'EOF'` body, `grep V <<'EOF'` body,
   `sed -n p README.md # V=1`, `git log -SV=1`.
3. Approval path, tested in a throwaway repo. The exact intended command
   (with the real paths) exits 2 with only
   `rule (f) golden-write: RT_DEMO_BLESS or RT_APP_GOLDEN_BLESS regenerates goldens`;
   it carries the `unshare` wrapper, so rule (e) does not fire. After
   `golden_approve.approve_command` for that string it exits 0 once, then 2
   again. The same command with the variable replaced by `FOO=` exits 0, so
   (f) is triggered by the variable alone.
4. Suite: 109 tests, OK, in the scratch copy (the 111 in the run that
   included my extra file also passed).
5. Red evidence: the changed test file run against the HEAD
   `guard_shell.py` (`git show HEAD:tools/hooks/guard_shell.py`) in a second
   scratch copy: `GuardShellGoldenWrites` ran 10 tests, 9 failures: 8 for
   each new blocked form and 1 for the approval-lifecycle test. The three
   new read-only forms pass on both versions, as expected (they are
   non-regression checks).
6. No other rule weakened: the diff touches only the regex literal, one
   regex, one message string and the docstring. No existing test line was
   removed or changed (diff shows additions only in the test file).
