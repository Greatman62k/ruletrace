## 4. Non-blocking findings

1. RT-EXE-0011's meaning text changed ("Published result differs from computed Outcome" to "Published value differs from the computed value (kind value_differs)"). Code, mnemonic, severity and exit code are unchanged, so it is not a renumbering. Req 7.2 and 7.11 require meaning text to stay byte-identical across releases. No release tag or baseline file exists, so `check-catalogue` skips the baseline ("baseline skipped: no release tag exists, Req 7.12"). The change is legitimate only because it precedes the first release. After the baseline is committed, the same edit fails the compatibility test. The 13.12 text assigns RT-EXE-0011 to `value_differs` only, so the narrowing is justified. The decision record states it ("The RT-EXE-0011 meaning text now says value difference only").
2. The CLI-level Indeterminate test (`a_difference_with_an_indeterminate_ranking_is_rt_exe_0011_and_exit_4`) does not detect a classifier that ignores Indeterminate (mutant M6). The engine tests in `tests_published_ranks.rs` do detect it. Coverage is adequate in aggregate. There is no CLI-level test that mixes all three kinds in one run. I ran one as a scratch test (see 5), since reverted.

## 5. What held up

(a) 13.12 text. I extracted the proposal block from `docs/requirements-amendments.md` with a script. It occurs verbatim in the 13.12 line. Removing it and the added CLI sentence reproduces the 1cf1340 line exactly (script printed True and True). The only added wording is: "THE CLI evaluate command SHALL report each difference as one Warning Diagnostic whose code follows its kind: RT-EXE-0011 for `value_differs`, RT-EXE-0012 for `tie_broken_without_declared_criterion` and RT-EXE-0013 for `tie_not_in_computed_result`, and a difference SHALL NOT change the exit code." This names the codes and is accurate against `evaluate.rs` and the catalogue. The rule "a split needs at least two distinct published positions among the listed members" is not a literal sentence in 13.12. It is implied by "gives different positions to participants of one computed Tie_Group". The approved amendment placed it in the "Behaviour implemented" list, not in the inserted block, so the insertion matches the approved text. Design §3.6.3 (rank paragraph), the §4.3 table (three rows) and the §9.4 RN-26 row agree with 13.12 on kinds, codes, Warning and no exit-code change.

(b) Catalogue. The diff adds only RT-EXE-0012 `PUBLISHED_TIE_GROUP_SPLIT` and RT-EXE-0013 `PUBLISHED_TIE_NOT_COMPUTED`, both Warning, exit 0, `rt evaluate`. The naming is consistent with the existing PUBLISHED_RESULT_DIFFERS. RT-EXE-0011's only change is its meaning text (finding 1). No code was removed or renumbered. `gen-catalogue` run in the worktree left `git status --porcelain` empty, so the committed generated file equals a fresh generation. `check-catalogue: ok (154 codes)`.

(c) Evaluate path. `difference_code` in `evaluate.rs` maps each `DifferenceKind` to one code, with a match that has no wildcard arm. Hand-written CLI tests assert exact stderr text for each kind. I ran a scratch mixed run on p1=p2=1 (computed), p3=3, p4=4, p5=5, published p1=1, p2=2, p3=4, p4=4, p5=9. It gave exit 0, with RT-EXE-0012 for p2, RT-EXE-0013 for p3 and RT-EXE-0011 for p5, in participant order. The Indeterminate case (p4 has no age) gave exit 4 from RT-EXE-0006 (catalogue exit 4), with the published difference as warning RT-EXE-0011 only and no 0012 or 0013. A Warning never changes the exit code (catalogue exit 0 for all three, mutants M3 and M4 killed).

(d) Goldens. `git diff --stat 1cf1340..11b0905 -- demo tests` is empty. `rt-demo` tests: all 12 test binaries ok (30, 9, 1, 4, 5, 1, 4, 2, 39, 3, 2 and 0 tests; 0 failed, 0 ignored). The demo golden `s06b.stderr` still contains `warning RT-EXE-0011` for a `value_differs` case.

(e) `catalogue_ud37.rs`: `147 + RESERVED.len()` became `147 + RESERVED.len() + 2`. The assertion stays exact, and the per-code checks in that file are unchanged. Not a weakening.

(f) The expected values in `tests_published_kinds.rs` are literal strings written from the 13.12 text and a hand-computed ranking (positions 1, 1, 3, 4). `catalogue_rn26.rs` uses literal ids, mnemonics, Warning severity and exit 0 from the decision. Neither file calls the production code to build its expected output. Comments are on their own lines.
