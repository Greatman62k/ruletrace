## 5. Non-blocking findings

**M1. Prototype versus draft: the duplicate Authorization header.** The prototype
does refuse it: `lab.rs:51` uses `single_header("Authorization")`, which returns
`None` for two values (`http.rs:34-39`), so `authorized` is false and the
response is 401 with a challenge (`lab.rs:103-108`). The draft is therefore not
beyond the prototype in behaviour. The prototype has no test of it: the only
repeated-header test is `http.rs:227` and it uses `Host`. The 13.4 test for draft
37.7 must add one (two Authorization headers, one of them valid).

**M2. Prototype Origin check is narrower than Req 37.4.** `lab.rs:98` checks
Origin only on POST and accepts only the exact origin. Req 37.4 (requirements.md:1311)
also refuses any request, GET included, with a wrong Origin, covers PUT, PATCH
and DELETE, and accepts `Sec-Fetch-Site: same-origin` when Origin is absent.
UD-45:12-13 ("for a state-changing request, Origin") describes the prototype, not
37.4. The draft 37.7 correctly refers to "the Origin check of criterion 4", so
the draft is consistent with 37.4. Suggest UD-45 section 1 say "the Origin check
of Req 37.4" so the decision does not read as narrowing it. The browser protocol
and 13.4 tests must exercise the 37.4 form, which the prototype did not.

**M3. Scope label.** The title (UD-45:4), design.md:3631, and threat-model row
LT-6 say "Req 37.5 to 37.7", but section 4 drafts 37.5 to 37.9, 37.19, 37.22,
37.24 and two definitions. design.md:3555 and 3627 still say "Req 37.5 and 37.6".
Harmless while nothing is applied. Use one wording ("Req 37 criteria 5 to 9, 19,
22, 24 and two definitions") when the amendment is applied.

**M4. Criteria missing from the update list.** Still not named: 37.18
(requirements.md:1322, "no ... session identifier" in the session directory, now
harmless but stale), 37.25 (line 1333, the test "attempt to establish a second
independent Laboratory_Session": under option A there is no exchange to attempt,
so the test needs new wording, for example credentials presented from a second
tab), and the RN rows at design.md:3185 and 3187 (named only as "RN rows that
mention the cookie"). Draft 37.9 also leaves open when the CSRF token is first
issued (the first authenticated page); say so in the criterion.

**M5. Kill harness: no minimum for "during the write".** UD-45:53-55 makes a
platform inconclusive only if zero trials land in the write window. One landing
trial would then count as evidence. State a minimum M (for example 10) or report
M beside the verdict as the text already says for the result line. "Measured
duration of its write phase" does not say how it is measured without a production
hook; say it is observed from outside the process.

**M6. Idle clock and unused secret.** Draft 37.8 counts 30 minutes "no request"
but does not say whether a refused request (401 or 403) resets the idle timer,
and an unused Launch_Secret has no expiry (R-L7 stays, as listed). The first
point is inherited from the current 37.8, so it is not a regression; decide it
when applying the wording, since an attacker's 401 requests could otherwise keep
a session alive.
