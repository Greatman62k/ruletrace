## 5. What held up

1. **Requirement text against implementation.**
   `machine.rs:386-396` pushes `diagnostics_scope` right after the
   `diagnostics` member. `ReportSection::rank` (`model.rs:1020-1028`) puts
   Diagnostics last (5), and `ReportDoc::new` sorts by rank, so the member is
   immediately after `diagnostics` and the last top-level member in both
   kinds. The constant `DIAGNOSTICS_SCOPE = "evaluation_and_provenance"` is in
   `common.rs:20`. The human heading (`common.rs:23`, used at `human.rs:341`)
   states evaluation and provenance, published differences under PUBLISHED
   CONSISTENCY, and standard-error warnings outside. The heading is
   hard-coded independently in the test file (`tests_app_report.rs:24`), not
   imported from production.
2. **Consistency of 31.16 with 31.6, 32.5, 31.7, 31.13, 31.14, 32.1, 32.2.**
   31.6 and 32.5 reference 31.16 by number. 31.7 and the published section
   keep the differences, with code. No ordering or element-order rule (31.13)
   is changed. 31.14 (provenance) and 32.1/32.2 are untouched. I found no
   contradiction.
3. **Traceability.** A script compared each traceability `Old:` text with
   `git show 3ed212c:.kiro/specs/ruletrace-compiler/requirements.md`:
   31.6 old text found (True), 32.5 old text found (True), 31.16 old text is
   `(none)`. Each `New:` text is found verbatim in the new requirements.md.
4. **UD-42 against the user decisions.** F1 (type string, mandatory, exact
   value, meaning split into evaluation plus provenance, published
   differences separate, standard-error warnings outside, Prize and Bracket,
   design note kept as rationale, nothing else changed) and F2 (a genuine
   evaluation Diagnostic, no API change) are both recorded. design.md changes
   one sentence appended to the §8.5 note. UD-42 appears in the requirements
   decision list.
5. **Field sets and order.** `FIELD_SET_PRIZE` and `FIELD_SET_BRACKET` each
   contain `diagnostics_scope`. `key_paths_equal_the_exported_field_sets_exactly`
   and the property tests compare every key path in both directions, and the
   hand-written JSON documents fix the order. Mutants m1-m3 below killed.
6. **Separation.** A workspace grep for `PublishedResultDiffers`,
   `PublishedTieGroupSplit`, `PublishedTieNotComputed` and `RT-EXE-001[123]`
   shows none in any `ReportSection::Diagnostics(...)` constructor. The four
   constructors are `tests_app_fixtures.rs:346,378` and
   `tests_app_report.rs:671,892`, and they hold `RT-EXE-0001` or nothing.

   both fixture documents p2 has an Indeterminate score trace with missing

   copies the engine message shape verified in `bracket-check`
   `tests_diagnostics.rs` ("rule X: required input 'Y' of participant 'p2' is a
   Missing_Value"). The escape test still passes a control-character message
   (`"line\u{1b}[0m\n"`) and asserts `line\u{1b}[0m\u{a}   at` in the human
   output, so escaping in a Diagnostic message is still tested.
7. **Both formats.** Human and JSON expected layouts changed together
   (`:142`, `:247`, `DIAG_JSON`). The published-difference-only test is
