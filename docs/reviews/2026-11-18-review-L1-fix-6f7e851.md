## 4. Non-blocking findings

Severity is low for all.

- **F1. RN-33 text was not updated, but §11.7 says it asks the user to choose.** `design.md:3368` ends "RN-33 asks the user to choose" between a workspace ledger written directly by `ruletrace review` and an export. The RN-33 row at `design.md:3146` still asks only "allow a byte-identical, hash-recorded copy before any review, and nothing else". The consequence (decisions live in the session copy and are deleted by 37.17) is therefore not in the register where the user decides. The first option also conflicts with the stated purpose "so that `review approve` never changes a committed file". Add the question to RN-33 or a new RN. (Prior N9.)
- **F2. The new limits are not labelled as design values.** `design.md:3401-3403` (10 s header deadline, 30 s body deadline, 16 connections) and `threat-model:153` give them without saying they are design values. Their "Basis" cell is "threat model T12", which differs from the "Req 37.14" cell of the requirement-derived rows, so they are not presented as requirement text. Still, neither Req 37 nor any OPEN item (LT-8 covers uploads only) states or lists them. Add "design value, not in Req 37, no OPEN item" or add them to LT-8. The same gap remains for the mutant list: RN-48 (`design.md:3161`) extends 37.23 to criteria 6, 21, 24, 25, 26, but 36.4, 36.6 and 36.9 still have no required mutant. (Prior N11, partly.)
- **F3. T30 is stale.** `threat-model:197` still says "One state-changing operation at a time per session" without the `POST /session/end` exemption that `threat-model` §7 and `design.md:3340` now state.
- **F4. T12b over-claims.** `threat-model:155` says "every POST answers 303 to a GET". Refused POSTs answer 400, 401, 403, 409 or 413 (`design.md:3341`, T12). Say "every accepted POST". I did not check how the design treats HEAD; T12b also states HEAD has no side effect.
- **F5. The Launch_Secret exchange during a running step is an unrecorded departure from the literal 37.25.** `design.md:3337` says a second exchange gets 401 "also while a step runs ... no session mutex applies". Req 37.6 requires 401 for a second presentation, so the design follows the more specific criterion, which is defensible. But `POST /session` is a POST (37.9), and RN-45 (`design.md:3158`) names only `POST /session/end` as the exception to 37.25. Add the exchange to RN-45.
- **F6. The Windows statement in T23 is asserted before it is verified.** `threat-model:180` says the directory under the user's temporary directory "inherits its owner-only ACL" and then says L2 must verify it. As far as I know, a default temporary-directory ACL on Windows also grants SYSTEM and Administrators, so "owner-only" may be wrong; I did not test this. Reword to "inherits the ACL of the user's temporary directory; L2 must verify who else has access". The device-name, `\\?\`, `\\.\` and alternate-data-stream refusals are stricter than 37.13 and need no RN, but no 37.23 test or mutant covers them.
- **F7 (record only). `traceability.md:996` now holds the reviewer's finding inside the user-approved decision row.** The parenthetical "(the check found no snapshot and no CSV fixture yet, so the values stay Recommended-pending, LT-8)" is accurate and matches `design.md:3415`. It sits in a row headed as the user's approved text. Consider moving it to a separate note so the user's wording stays separable from the author's.
