# RT-AI-0309 directory-sync-skipped warning and run-summary header

Commit 8fdfe97 adds the Warning `RT-AI-0309` (`AI_STORE_DIRECTORY_SYNC_SKIPPED`, exit 0, location command `propose`). The run emits it once when at least one batch it stored had its directory sync skipped by the platform. The Run_Summary header becomes `complete, directory durability not confirmed` for a complete run with a non-empty skip list. An incomplete run keeps the plain `incomplete`. Commit 753b982 adds `--no-fail-fast` to the `test` and `core-only` cargo test steps in CI. Requirements 7.17, 23.36, 23.38 and 29.19, design 3.7.5 and 3.7.7, the traceability file, the catalogue and the generated `Code` enum are updated together.

Watch for: the `test (windows-2022)` CI job will most likely fail, because real-filesystem tests (about 60 `run_std` call sites, not all asserting success text) expect the Unix summary and no warning (confirmed by reading the tests, not run on Windows). The commit's own traceability note says so and leaves them unchanged.

**Verdict**: NEEDS_CHANGES

## High-level view

The warning is emitted once, after the loop in `run_requests`, from the same `unsynced` list that already feeds the summary section. Its exit code and severity come from the catalogue, so it cannot change the exit code, and the exit is computed before the warning is pushed. Ordering relative to `RT-AI-0306` follows the existing Diagnostic ordering and is asserted.

The header change is a three-arm match on (complete, skip list empty). It is narrow and matches the amended requirement text exactly.

The catalogue, requirements table, design table and generated enum agree on code, mnemonic, severity and exit. The generator drift check (`rt-xtask check-catalogue`) passes, and I confirmed it fails when the generated file is edited by hand.

The new tests are hand-derived and detect every mutant I tried. The weak point is the platform. Commit 8fdfe97 knowingly leaves Unix-only expectations in tests that run on Windows, and 753b982 makes CI report all of those failures rather than stop at the first.

## Warning emission and exit-code neutrality

The push sits after the `RT-AI-0306` push in `run.rs`, so the in-code order agrees with the sort order the CLI applies, and the test `the_skip_warning_orders_after_the_incomplete_run_warning` checks it on sorted output. The exit value is derived from the failing request before either warning is pushed, and the catalogue gives 0, so a skip plus a provider failure still exits 5 (`a_skip_followed_by_a_failure_keeps_the_incomplete_header_and_warns`). A failure before any skipped batch emits no skip warning, and a failed request that returned `KeptUnconfirmed` goes to a different list, so a failed sync is not double reported. Warning never changes compilability is not affected, since this code is only in the `ruletrace-ai` path.

## Header text and honesty of the claim

The incomplete case drops the note on purpose. The summary still carries the skip under its own heading, and `RT-AI-0309` is emitted. The decision is documented in Req 23.36, design 3.7.7 and traceability, and the mutant that adds the note to `incomplete` is killed. The docs state the Windows limit plainly ("a power loss shortly after a store write may lose the directory entry"), and the new reason ("the standard library cannot open a directory for a flush on Windows") is more accurate than the previous "a directory cannot be opened". Item 3 above is the one place where the output after a rerun says less than is known.

## Windows tests still assert Unix behavior

`StdFs` skips the sync on every non-Unix platform since 92d87f6. Tests that go through `run_std` or `StdFs` and expect a success then see `complete, directory durability not confirmed`, a non-empty skip section, an empty `stored:` list and one `RT-AI-0309` on stderr. Examples: `tests_cli_run.rs:58`, `tests_revise.rs:190`, `tests_gate_failures.rs:322`, plus the `tests_cli_order`, `tests_revise_target` and `tests_store_invalid` users of `run_std`. The only real-disk test adapted in 8fdfe97 is `two_runs_on_one_real_disk_store_each_batch_once`, and it was made conditional on the actual skip list, which keeps the assertion exact on both platforms. The traceability note states that the others "are not changed here and will differ on Windows". With 753b982 all of them will now be listed in the Windows job log instead of stopping the job at the first one. The Windows job will fail (likely, not run here). The fix is not to relax the assertions. Write Windows-specific expected text with `cfg(windows)` or move the cases to `MemFs` faults, which the new `tests_dir_sync_skip.rs` already shows how to do.

## CI change

`--no-fail-fast` on `test` and `core-only` only changes how many failures are reported. It does not change the job result, and `pipefail` is still set, so the `tee` does not mask a failure. No test is skipped or loosened. Nothing wrong here, except that its benefit is currently to expose item 1.

## Test quality and mutant check

Expected values in `tests_dir_sync_skip.rs` are literal strings and codes written from the requirement, not produced by the code under test. They cover: a single warning with exit 0 and location `propose`, no warning when nothing is skipped, a mixed run (one synced, two skipped), a skip then a failure, a failure before any skip, a rerun that changes nothing, ordering against `RT-AI-0305` and `RT-AI-0306`, and the real command writing the warning once to stderr and not to stdout.

Mutants I ran against the `rt-ai-tool` lib tests (files restored afterwards, tree clean):

- Remove the warning push: killed (8 tests).
- Emit when `stored` is non-empty instead of only when `unsynced` is non-empty: killed (many, including `only_a_run_that_stored_a_skipped_batch_warns`).
- Header ignores the skip list: killed (4 tests).
- Add the note to `incomplete`: killed (2 tests).
- Change the exit code of the generated `Code` entry to `Internal`: killed by `the_skip_warning_is_one_warning_with_exit_0_at_the_command`. The `rt-foundation` tests alone did not detect it. `rt-xtask check-catalogue` did, reporting generated-file drift.

Not mutated: the sort order of the two command-located warnings (the order test would need a swapped code to be meaningful), and the message text, which no test asserts. Only the code, severity and location are asserted.

Existing assertions changed in 8fdfe97: `tests_run.rs` (diagnostics empty becomes one `RT-AI-0309` warning, header text) and `tests_summary.rs` (header text). Both follow the amended requirement and are strengthened, not weakened. No golden file changed and no test was ignored or removed.
