## 4. Non-blocking findings

- **N1** `traceability.md:1326`: the row labels Req 37.17 "children terminate on crash". Req 37.17 (requirements.md, Requirement 37 item 17) covers orderly shutdown and signals: close the listener, terminate each subprocess, exit 0. Crash containment comes from design §11.18.6 and RN-50, which design.md:3189 maps to 37.17. Task 13.9 itself cites 37.17, so the mapping is defensible, but the paraphrase misstates the requirement text. Suggest "(shutdown, subprocess termination; crash containment via RN-50)".
- **N2** `lt7-lifeline-evidence.md:55-61` and `crash.rs` `d_closing_the_pipe...`: the orderly-close time is observed by `wait_exit`, which polls every 10 ms. Linux and Windows report exactly 10, so these two values are at the polling quantum and mean "at most about 10 ms", not 10 ms. Section 2 describes the 5 ms polling for kill-to-gone but not the 10 ms for orderly close. The numbers are quoted correctly. Add one sentence.
- Minor, no action needed: `tasks.md:1702` and the review row at `threat-model:365` say "reviewed in" this report, and `tasks.md:1702` names it before it existed. That is accurate once this file is written. If the verdict were not APPROVED, the cited rows would need changing.
- Minor: the record says "Windows Server build 20348". The system log gives only `MINGW64_NT-10.0-20348` (label `windows-2022`). Build 20348 is Windows Server 2022, but the log does not state "Server".
