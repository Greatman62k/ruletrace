## 4. Non-blocking findings

**1 (Low): F2 of review 9.11 is only partly fixed.**
Two claims are wrong or too weak.

- The status note says "`with_cases` ignores `PROPTEST_CASES`". It does not.
  The proptest runner applies `contextualize_config` to the configured value
  (proptest 1.12.0, `test_runner/config.rs:17-20`). Evidence: the property
  test ran in 54.3 s with `PROPTEST_CASES=600`, 25.0 s with no variable, and
  0.40 s with `PROPTEST_CASES=3`, and all five tests passed in each run.
  `the_property_runs_at_least_256_cases` stayed green with `PROPTEST_CASES=3`,
  because it inspects `ProptestConfig::with_cases(CASES).cases`, a struct
  value that the runner later overrides.
- The check is not tied to the config that the `proptest!` block uses.
  Mutant: `#![proptest_config(ProptestConfig::with_cases(10))]` in the macro
  survived (5 passed, 0.84 s). Only changing `CASES` is caught, by the
  compile-time `const _: () = assert!(CASES >= MIN_CASES)` (E0080). The
  runtime test repeats that same constant check against the literal 256, so it
  adds nothing the const assert does not already cover.

No CI file sets `PROPTEST_CASES` (`grep -rn PROPTEST .github .cargo Cargo.toml
tools`: no match), so the real run is 256 cases today. Suggested fix: one
helper that builds the config and is used by the macro, and a test that reads
the number of cases that actually ran (a counter in the property body). Also
correct the status note and the doc comment "whatever the environment says".

**2 (Info): stale names in a doc comment.** The doc comment of
`the_reference_model_matches_a_hand_derived_tie` (about lines 794-805) says "p03
and p04 both score 3 ... p04 (19) before p03 (20)". The code uses `p01` (age
20) and `p02` (age 19). The assertion is right: p02 first.

**3 (Info): dates.** The integrity note and the usage-log row are dated
2026-11-18, the commits 2026-11-19. Other entries in the repository use the
same convention; I did not verify which is intended.
